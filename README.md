# TradingBots — Автоматический торговый бот

Проект бумажного трейдинга на Python. 4 бота под разные режимы рынка,
Market Regime детектор, ML фильтры, автоматический журнал сделок.

---

## Архитектура

```
market_regime.py (каждые 30 мин)
  ├── TREND_UP / TREND_DOWN → Бот #1 Адаптивный  (Bitget spot, 5m)
  ├── SIDEWAYS              → Бот #1 + Бот #2     (Bitget / Binance)
  ├── BREAKOUT              → Бот #4 Breakout     (Binance, 15m/1h)
  └── VOLATILE              → пауза

Бот #3 Funding Rate — работает независимо от режима (Bitget фьючерсы, 1h)

shared_state.json ← market_regime.py пишет каждые 30 мин
      ↓
все боты читают режим → выбирают стратегию входа
      ↓
ml_data_collector.py → единый датасет (regime, signal_type, exchange, ...)
```

## Боты

### Бот #1 — Адаптивный (Bitget spot, 5m)
**Режим:** TREND_UP / TREND_DOWN / SIDEWAYS

**Стратегия меняется по режиму рынка:**

```
TREND_UP / TREND_DOWN → Channel Breakout
  Пробой 15-свечного канала с объёмом > 1.5x
  Вход на закрытии пробойной свечи
  Стоп за противоположный край канала
  RR 1:3

SIDEWAYS → Mean Reversion
  RSI < 35 + цена у нижней BB (±1%) → лонг к средней BB
  RSI > 65 + цена у верхней BB (±1%) → шорт к средней BB
  BTC медвежий → MR_ЛОНГИ заблокированы (WR 36% без фильтра)
  Объём < 3x, стоп 0.2-0.4%
  RR 1:2

VOLATILE → пауза
```

**ML фильтр:** Random Forest, AUC 0.608, порог 0.40
Каждый сигнал проходит ML перед добавлением в pending.

**Параметры:**
```python
timeframes       = ["5m"]
channel_bars     = 15       # свечей для канала
bo_vol_mult      = 1.5      # объём на пробое
min_breakout_pct = 0.001    # минимальный пробой 0.1%
rsi_oversold     = 35
rsi_overbought   = 65
min_stop_pct     = 0.006    # стоп <0.6% — комиссия съедает >33% риска
max_stop_pct     = 0.03     # стоп >3% — слишком широкий для 5м
min_rr_mr        = 1.5      # минимальный RR для MR сигналов
bad_hours        = [14, 21, 22]
exchange         = "bitget"
```

**Статистика:**
```
Всего (старая стратегия): 604 сд  WR=23.5%
Новая стратегия (с 01.04): 20 сд  WR=50%
  MR_ШОРТ: WR=67%  PnL=+$4.35  ✅
  MR_ЛОНГ: WR=36%  (до фильтра BTC тренда)
  Channel BO: 0 сд (рынок пока не даёт пробоев)
```

### Бот #2 — Mean Reversion (Binance, 15m/1h)
**Режим:** SIDEWAYS

**Стратегия:** RSI + BB + ML фильтр, только ЛОНГИ

```
ШОРТЫ ОТКЛЮЧЕНЫ — математически убыточны:
  RR реальный 0.54 (WIN +$1.15 / LOSS -$2.12)
  Точка безубытка WR=65%, факт WR=42% → разрыв -23%
  107 сделок: SHORT PnL = -$32.35

ЛОНГИ работают:
  RR реальный 1.58 (WIN +$2.44 / LOSS -$1.54)
  Точка безубытка WR=39%, с ML фильтром WR=45%
```

**ML модель:** Random Forest, AUC 0.723 (только лонги)
OOS AUC 0.686, при пороге 0.40 WR=45% на тесте.

**Параметры:**
```python
timeframes     = ["15m", "1h"]
adx_max        = 25
rsi_oversold   = 30
rsi_overbought = 70   # не используется (шорты отключены)
min_rr         = 1.5
rr             = 2.0
```

**Статистика:** 107 сд, WR=36.4%, последние 20 сд WR=35%

### Бот #3 — Funding Rate (Bitget фьючерсы, 1h)
**Режим:** любой (лучший в TREND_DOWN)

**Стратегия:** контрариан по Funding Rate

```
FR < -0.03% → все шортят → ЛОНГУЕМ
FR > +0.03% → все лонгуют → ШОРТИМ
Подтверждение: RSI + BB
Лимитный ордер ±0.3%, RR 1:3
```

**Статистика:** 35 сд, WR=34.3%, PnL=-$38

**Наблюдение:** бот берёт малоликвидные монеты с аномальным FR.
ML модель исправит это автоматически после 60+ сделок с текущим WR.

## ML система

Обе обученные модели и весь датасет **потеряны** вместе с журналами
сделок (см. «Состояние» ниже). Но переобучать их по старой схеме и
не стоило — в подготовке данных были две утечки будущего:

| Что | Как было | Последствие |
|-----|----------|-------------|
| `hour`, `is_london`, `day_of_week` | считались от времени **закрытия** сделки | признака не существует в момент входа; на бою подставлялось время открытия — обучение и применение расходились |
| `regime` | брался на момент закрытия | то же самое |
| `risk_pct` (главный признак Bot1) | для сделок без стопа выводился как `abs(pnl)/deposit*entry` | вычислялся из реализованного PnL, то есть из ответа |
| Порог отсечки | подбирался на предсказаниях модели, обученной на всех данных | завышенный WR «при пороге» |

Поэтому **заявленные AUC 0.608 и 0.723 недействительны** — это не
измеренное качество, а следствие утечек. Критерий выхода на реал
«ML AUC >= 0.70» пока просто не проверен.

Утечки в коде закрыты: время и режим берутся на момент входа, риск
не выдумывается (есть флаг `has_stop`), боты сохраняют в сделке
`opened/stop/take`. Новые модели имеет смысл обучать на сделках из
бэктеста — их тысячи, а не десятки.

## Бэктест

Проверка стратегии на истории вместо ожидания месяцами. Стратегия
не переписана — `Backtest/run.py` импортирует настоящие
`add_indicators` и `find_signals` из самого бота, поэтому бэктест и
бот не могут разойтись.

```bash
# Прогон за 3 месяца по 25 инструментам
python Backtest/run.py --start 2026-06-01 --end 2026-09-01 --symbols 25

# Сравнить модели исполнения
python Backtest/run.py --compare-fills

# Перепроверить каждую сделку по сырым свечам
python Backtest/validate.py
```

Чем модель исполнения отличается от бумажной торговли:

| | Бумажный бот | Бэктест |
|---|---|---|
| Стоп/тейк | опрос цены раз в 10 мин | high/low каждой свечи |
| Лимитка | цена подошла на ±0.3% | цена дошла до уровня |
| Проскальзывание | нет | есть на стопах |
| Плечо | не проверялось | объём режется под депозит |
| Стоп и тейк в одной свече | — | засчитывается стоп |

Ключи: `--fill limit|touch|market`, `--leverage`, `--risk`,
`--deposit`, `--slippage`, `--symbols`.

Свечи кэшируются в `Backtest/cache/`, поэтому из сети качается
только первый прогон.

### Первый результат (июнь–август 2026, 19 пар, 990 сделок)

```
WR 29.6%   точка безубытка 34.7%   profit factor 0.79   итог -88.6%
```

Стратегия убыточна, но интересно **почему**:

| | на сделку |
|---|---|
| Валовый край | **+0.048R** |
| Комиссия | **−0.207R** |
| Итого | −0.158R |

Край есть — он положительный. Но комиссия больше него в 4.3 раза.
Средний стоп 1.21% от цены, комиссия туда-обратно 0.2% — то есть
17% дистанции стопа отдаётся бирже на каждой сделке. При 990
сделках за три месяца это $36.91 комиссий на депозит $50: **83%
всего убытка — комиссии**, до них результат почти в нуле (−$7.39).

Разрез по ветвям стратегии (валовый R на сделку):

| Сигнал | Сделок | WR | До комиссий | Чистое |
|--------|--------|----|-------------|--------|
| MR_ЛОНГ | 120 | 35.0% | **+0.152R** | −0.121R |
| MR_ШОРТ | 351 | 34.5% | **+0.122R** | −0.149R |
| BO_ЛОНГ | 272 | 27.6% | **+0.077R** | −0.070R |
| BO_ШОРТ | 247 | 22.3% | **−0.138R** | −0.286R |

Три ветви из четырёх зарабатывают до комиссий. `BO_ШОРТ` убыточен
и до них — его надо отключать, ровно как в своё время отключили
шорты Bot2 по той же причине.

Отсюда направление работы: не «искать сигналы получше», а снижать
трение — реже сделки, шире стопы, старший таймфрейм, мейкерские
заявки вместо тейкерских.

**Оговорки.** Список пар построен по сегодняшним объёмам
(survivorship bias). Три месяца — один рыночный режим. Депозит $50
при 990 сделках означает, что размер позиции всё время упирался в
лимит плеча (100% сделок урезаны), поэтому долларовые суммы искажены
и смотреть надо на R.

Модели исполнения `limit` и `touch` дали **идентичный** результат:
вход ставится по цене закрытия сигнальной свечи, поэтому лимитка
исполняется в 100% случаев и поблажка ±0.3% ничего не меняла. Для
этой стратегии она была безвредна — но проверить это стоило.

Проект возобновлён после полугодового перерыва.

**Данных нет.** Журналы сделок, ML-датасет и обе модели не

+ 35 (Bot3) + 13 (Bot4). Уцелел только `ML/regime_history.jsonl`
(454 записи) — случайно, потому что попал в репозиторий вопреки
тому, что написано в заметках.

Поэтому все цифры WR и PnL из прошлых версий этого README
(23.5% / -$440 и прочие) больше ничем не подтверждены и убраны.

**Что было исправлено при возобновлении:**

- проект не запускался: пути вели в несуществующую папку, не были
  установлены `pandas` и `scikit-learn`;
- автопополнение депозита молча возвращало баланс к стартовому при
  сливе — эквити-кривая рвалась, просадка не считалась, восемь
  сливов подряд выглядели как одна просадка;
- две утечки будущего в подготовке ML-данных (см. выше);
- `get_symbols` брал 80 пар с наибольшим оборотом, а на Bitget весь
  топ по обороту — **токенизированные акции** (RNVDA = NVIDIA,
  RQQQ = ETF QQQ), их там 1178 против 513 криптовалютных пар. То
  есть бот торговал акциями, хотя стратегия строилась на крипте;
- `print()` с эмодзи падал с `UnicodeEncodeError` в консоли Windows
  и ронял торговый цикл.

**Чего пока нет:** подтверждённого преимущества стратегии. Оно и не
было подтверждено раньше — все четыре бота закрыли период в минусе.
